# Threat model

Required before launch; reviewed in the PR that opens the challenge.
Answer every question. "N/A" needs a reason.

## How could a wrong answer pass the verifier?

- Finite or reusable inputs (is the input set fresh per run? how many?): each run draws 600 valid txs + 300 mutants with CB_SEED, plus 4 fixed edge cases. CI scoring (submission and promote workflows) sets CB_POOL=fresh, so setup.sh fetches a new pool from random mainnet blocks in the last ~7 days (`verifier/pool.py`, 250 blocks drawn with os.urandom, at least 1,200 txs). That pool isn't in the repo and doesn't exist when the submission is written, so a table of decoded txs can't pay. The repo pool (`corpus/pool.hex.gz`, 1,633 txs, epochs 645-666) is public and is only for local runs and preflight. A table of it would only fool a local score. max_bytes (4 MiB) leaves ~1.6 MB over the 2.6 MB baseline, enough to table that pool, so scores on the repo pool mean nothing on their own. Mutants are fresh each run and can't be tabled.
- Caching or precomputation (can a table or memo pay off without knowing the seed?): scoring decodes each sampled tx once, and start-up is subtracted, so a cross-call memo has nothing to reuse. The repeat loop only runs for the wall-time guard. A global memo needs unsafePerformIO, an IORef or similar, which are banned.
- Reading the reference, oracle, seed or expected output: the decoder is a pure library. `cb gate` runs an allowlist over src/ against the baseline (`crates/cb/src/haskellpolicy.rs`, #51), after lexing the way GHC does, so pragma case and spacing don't matter. Pragmas other than INLINE/UNPACK-style ones must appear verbatim in the same baseline file (no new OPTIONS_GHC, -pgmF, ANN, RULES or INCLUDE). LANGUAGE extensions must be on a safe list or already in that file. MagicHash, unboxed tuples/sums and unlifted types are allowed only where that baseline file has them (upstream: UnboxedTuples in core's Coin.hs). TH, QuasiQuotes, FFI and PackageImports are never allowed. CPP lines must be in the baseline file. Imports must be package-local, plain pure modules, or imported by the baseline. GHC.*, Foreign.*, System.*, Data.Primitive*, Control.Monad.ST*, *.Internal and the like must match a baseline import declaration exactly, and GHC.Exts/GHC.Prim/GHC.Base/GHC.ST/System.IO/Debug.Trace/Codec.CBOR.Magic only as an exact copy of an import in the same baseline file (upstream: GHC.Base (Type), Debug.Trace (trace)). No foreign declarations, and no more unsafe* / runRW# / realWorld# uses per identifier than the baseline. The src/ file set is frozen. Residual: the baseline imports Data.Primitive.ByteArray unrestricted, and unchecked ByteArray indexing can read nearby heap in ST. It can't reach the seed or the reference's output, which live in another process. Expected digests come from .bin/reference at verify time and are never written where the build can read them.
- Timing tricks (detecting the benchmark, doing less work when measured): there's no IO, so it can't see argv or env. The digest pass forces the full decoded value (show) and the re-encoded bytes, on the verify sample and on the exact txs that get timed. The timed pass forces it with rnf, and the candidate owns the NFData instance for Sized, so a digest can't show what rnf forced: verify repeats the timed decode + rnf and walks the heap with judge code (harness/HeapWalk.hs, no instance trusted). More unevaluated closures or more function closures than the reference leaves on the same tx is a reject (preflight/broken/lazy); that is any at all on almost every tx, as upstream's own rnf leaves a few thunks only on some tx shapes. Not covered: an rnf that skips walking data the decoder already evaluated saves the walk without decoding any faster; scoring decode-to-WHNF with a per-path laziness check against the reference would close that.
- Writing the score file directly, or editing anything outside the editable paths: the gate refuses files outside candidate/, symlinks and submodules. The candidate is only each package's src/ (same file set as the baseline); the cabal files, ghc-options, testlibs and tests come from the pinned clone, so they are frozen. Compile-time code that slips past the policy anyway runs in the build sandbox (`[build_sandbox]`, `cb score --sandbox`). It has no network and its own pid namespace and /proc, so nothing outlives the build. Supplementary groups are dropped (docker) and no_new_privs blocks sudo. `/run/user` is hidden, and `$HOME`, `/opt`, `/usr/local` and the workspace are read-only except `.bin/candidate`. Writes to the ledger and cabal caches go to a throwaway overlay deleted when the build ends, so nothing persists for later steps. So it can't rewrite the reference binary, the judge scripts, the checkout, the runner's action code or `$GITHUB_ENV`. Preflight probes the sandbox on Linux before building in it.

## Does the benchmark interface match real use?

Partly. The harness decodes full transactions the way the mempool receives them (`Annotator (MempoolTx ConwayEra)` at protocol version 11) with the node's own decoder. Block decoding takes the same body, witness and aux-data decoders, but splits them differently, and it isn't measured. We build without upstream's dev-only `+asserts` flags, as releases do; only the upstream test suites (#53) are built with them, as upstream's CI does. The src/ of cardano-ledger-binary, cardano-ledger-core and the Shelley..Conway era packages is editable, so the era instances (MaryValue, BabbageTxOut, the Conway tx body) are in scope. Those packages also hold the ledger rules, which the harness never runs: a change there can't move the score, and #53's upstream test suites are the check that it didn't break them. Only five of the eight suites gate a promotion (`upstream-tests.txt`: binary, core, shelley, allegra, mary). On the 2-vCPU runner the alonzo suite did not finish in 30 minutes and the babbage and conway suites were never reached, and the build is capped at 60 minutes, so a change that breaks only the Alonzo, Babbage or Conway ledger rules or a non-mempool decoder of those eras is not caught (#53 stays open for that).

## What is the known bound or headroom?

No published decode benchmarks were found (2026-11-06). Comparison points to measure: pallas (Rust) on the same pool, and plain decoding vs the Annotator path (the cost of keeping original bytes).

## What does a large outlier (+100%) trigger?

Manual review; never auto-promote.

- Who reviews: a SNF maintainer, plus a cardano-ledger contributor if one agrees. Reject parity is consensus-critical, so any change to what is accepted gets a human read even when it passes the verifier.
