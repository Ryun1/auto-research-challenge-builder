# Threat model

Required before launch; reviewed in the PR that opens the challenge.
Answer every question. "N/A" needs a reason.

## How could a wrong answer pass the verifier?

- Finite or reusable inputs (is the input set fresh per run? how many?): each run draws 600 valid txs + 300 mutants from a pool of 1,633 mainnet Conway txs (150 blocks, epochs 645-666) with CB_SEED, plus 4 fixed edge cases. The pool is public and finite. A hand-written table of decoded pool txs in source is possible, with no TemplateHaskell needed. max_bytes (1 MB, about 500 KB of headroom over the baseline) caps it below the 1.3 MB pool, but a partial table would still pay. **Open before launch:** grow the pool to 10k+ txs and score on a held-out pool that isn't in the repo. Mutants are fresh each run and can't be tabled.
- Caching or precomputation (can a table or memo pay off without knowing the seed?): scoring decodes each sampled tx once, and start-up is subtracted, so a cross-call memo has nothing to reuse. The repeat loop only runs for the wall-time guard. A global memo needs unsafePerformIO, an IORef or similar, which are banned.
- Reading the reference, oracle, seed or expected output: the decoder is a pure library. `cb gate` runs an allowlist over src/ against the baseline (`crates/cb/src/haskellpolicy.rs`, #51), after lexing the way GHC does, so pragma case and spacing don't matter. Pragmas other than INLINE/UNPACK-style ones must appear verbatim in the same baseline file (no new OPTIONS_GHC, -pgmF, ANN, RULES or INCLUDE). LANGUAGE extensions must be on a safe list or already in that file, and MagicHash, unboxed tuples/sums, TH, QuasiQuotes, FFI and PackageImports are never allowed. CPP lines must be in the baseline file. Imports must be package-local, plain pure modules, or imported by the baseline. GHC.*, Foreign.*, System.*, Data.Primitive*, Control.Monad.ST*, *.Internal and the like must match a baseline import declaration exactly, and GHC.Exts/GHC.Prim/GHC.Base/GHC.ST/System.IO/Codec.CBOR.Magic are never allowed. No foreign declarations, and no more unsafe* / runRW# / realWorld# uses per identifier than the baseline. The src/ file set is frozen. Residual: the baseline imports Data.Primitive.ByteArray unrestricted, and unchecked ByteArray indexing can read nearby heap in ST. It can't reach the seed or the reference's output, which live in another process. Expected digests come from .bin/reference at verify time and are never written where the build can read them.
- Timing tricks (detecting the benchmark, doing less work when measured): there's no IO, so it can't see argv or env. The digest pass forces the full decoded value (show) and the re-encoded bytes, on the verify sample and on the exact txs that get timed. The timed pass forces it with rnf, and the candidate owns the NFData instance for Sized, so a digest can't show what rnf forced: verify repeats the timed decode + rnf and walks the heap with judge code (harness/HeapWalk.hs, no instance trusted). Anything left unevaluated, or more function closures than the reference has, is a reject (preflight/broken/lazy). Not covered: an rnf that skips walking data the decoder already evaluated saves the walk without decoding any faster; scoring decode-to-WHNF with a per-path laziness check against the reference would close that.
- Writing the score file directly, or editing anything outside the editable paths: the gate refuses files outside candidate/, symlinks and submodules. The candidate is only each package's src/ (same file set as the baseline); the cabal files, ghc-options, testlibs and tests come from the pinned clone, so they are frozen. Compile-time code that slips past the policy anyway runs in the build sandbox (`[build_sandbox]`, `cb score --sandbox`). It has no network and its own pid namespace and /proc, so nothing outlives the build. Supplementary groups are dropped (docker) and no_new_privs blocks sudo. `/run/user` is hidden, and `$HOME`, `/opt`, `/usr/local` and the workspace are read-only except `.bin/candidate`. Writes to the ledger and cabal caches go to a throwaway overlay deleted when the build ends, so nothing persists for later steps. So it can't rewrite the reference binary, the judge scripts, the checkout, the runner's action code or `$GITHUB_ENV`. Preflight probes the sandbox on Linux before building in it.

## Does the benchmark interface match real use?

Partly. The harness decodes full transactions the way the mempool receives them (`Annotator (MempoolTx ConwayEra)` at protocol version 11) with the node's own decoder. Block decoding takes the same body, witness and aux-data decoders, but splits them differently, and it isn't measured. We build without upstream's dev-only `+asserts` flags, as releases do. The src/ of cardano-ledger-binary, cardano-ledger-core and the Shelley..Conway era packages is editable, so the era instances (MaryValue, BabbageTxOut, the Conway tx body) are in scope. Those packages also hold the ledger rules, which the harness never runs: a change there can't move the score, and #53's upstream test suites are the check that it didn't break them.

## What is the known bound or headroom?

No published decode benchmarks were found (2026-11-06). Comparison points to measure: pallas (Rust) on the same pool, and plain decoding vs the Annotator path (the cost of keeping original bytes).

## What does a large outlier (+100%) trigger?

Manual review; never auto-promote.

- Who reviews: a SNF maintainer, plus a cardano-ledger contributor if one agrees. Reject parity is consensus-critical, so any change to what is accepted gets a human read even when it passes the verifier.
